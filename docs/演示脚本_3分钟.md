# 3 分钟演示脚本（W4-3）

> 目标：让评委在 3 分钟内看懂三件事——**能玩**、**AI 真的在演**、**规则层可校验**。
> 录制：1080p、浏览器 100% 缩放、隐藏书签栏；提前打开两个标签页（创空间、GitHub）。

## 录制前 2 分钟准备

1. 打开 https://modelscope.cn/studios/mayi140611/lighthouse-seventh-night ，等页面完全加载（看到标题和「回合 0」）。
2. 点一下「重开」，确保从干净状态开始。
3. 确认右上「运行中」，模型显示 `modelscope`（不是 scripted）。
4. 关闭通知；麦克风试录 5 秒。

## 分镜

### 00:00–00:20 开场
**画面**：创空间首页，鼠标轻移到标题。
**旁白**：
「这是《灯塔第七夜》，一个 15 分钟的 AI NPC 互动叙事。风暴夜，最后一班船还有三小时，救生艇只有一个位置。三个人，三组可量化的状态，四个结局。」

### 00:20–00:45 界面与设计原则
**画面**：依次指右侧三个人物卡（信任/恐惧/亏欠）、底部「规则层日志」。
**旁白**：
「每个 NPC 有三个数值：信任、恐惧、亏欠。关键设计是：**大模型只负责提案，规则层负责裁判**。它给出的数值变化、记忆写入，先过契约校验，再由纯 Python 状态机决定采纳多少。结局也只由状态机计算，模型说了不算。」

### 00:45–01:35 第一段实玩：给面包、提钥匙
**操作**：
1. 点「给面包」→ 发送。
2. 停 2 秒，让观众看到「信任 +5、恐惧 -5、亏欠 +10」「已给出物资 1」。
3. 点「提钥匙」→ 发送。
4. 打开「规则层日志」，鼠标停在「提案 … → 采纳 …」这一行。

**旁白**：
「给船员面包，信任上升，但他会记住你答应过什么。现在要钥匙——如果信任不够，规则层会直接拒绝；够了，才会进入结局分支。日志里这一行就是证据：模型提案，规则层采纳。」

### 01:35–02:20 第二段实玩：换人、问真相、记忆引用
**操作**：
1. 点「老人」→ 点「问真相」→ 发送。
2. 指一下「记忆引用 N 次」。
3. 再发一句：“我之前给过你面包，还记得吗？”

**旁白**：
「换一个人，语气和筹码都不一样。老人知道灯塔真正的用途，但亏欠和恐惧会让他闭嘴。他还会主动提起你之前做过的事——不是换句说法，而是会改变他给不给你真相。」

### 02:20–02:50 结局与二周目
**操作**：
1. 继续追问/给物资，直到触发结局（最快路径：连续给老人两轮真相类提问，或按提示操作）。
2. 展示结局卡片。
3. 点「再来一局（保留记忆）」，展示 NPC 记得上一局。

**旁白**：
「四个结局：同舟、守灯、钥匙、第七夜。结局只由状态组合决定，可复现。二周目，NPC 会记得你上一局帮过谁——这是最便宜、也最像人的一个细节。」

### 02:50–03:00 收尾
**画面**：规则层日志 + GitHub 仓库页（README 架构图）。
**旁白**：
「代码开源，规则层有 94 个单测，四结局可离线复现。链接在简介里。灯塔的灯，交给你了。」

## 备用方案

- 模型偶发慢（>6 秒）：不要剪，画面上加一句「线上模型，实时生成」，等它出。
- 断网/额度不足：NPC 会用预置台词兜底，页面不白；此段可剪掉，不影响主线。
- 想更短：只录 00:45–02:20（75 秒版），发即刻/X 用。
