## 2. 玩法结构（15 分钟一局）

- 场景：风暴夜孤岛灯塔，最后一班船 3 小时后到，救生艇只有 1 个位置
- 3 个 NPC：船员（有钥匙）/ 少女（知道一半真相）/ 老人（知道灯塔的真正用途）
- 每回合：玩家自由输入 → NPC 回话 + 状态 delta → 面板变化
- 资源：面包 / 干柴 / 绷带 各 1 份，给出即改变对方数值，且会被记住
- 交叉验证：3 人证词有 2 处硬矛盾，问对问题才暴露
- 结局 4 个：同舟 / 守灯 / 钥匙 / 第七夜（由状态机按阈值组合判定，不由 LLM 选）

## 3. 技术架构：三层，边界写死

```
浏览器（单页，无框架）
   │  SSE 流式
   ▼
FastAPI（Python）
   ├── 规则层 StateMachine（纯函数，零 LLM 调用，可单测）
   │     · clamp(delta, -10..+10)
   │     · 阈值 gate：trust<40 拒交钥匙 / fear>70 沉默锁定 / debt≥60 说真话
   │     · 结局判定表（状态组合 → 4 结局）
   ├── LLM 适配层（OpenAI 兼容协议，可插拔）
   │     · 只做三件事：生成台词、提案 delta、抽取记忆
   │     · 输出必须过 JSON Schema + Pydantic 校验，越界/非法直接丢弃并重试 1 次
   └── 记忆层（SQLite / JSON）
         · memory[]：只存「玩家做过的事」+ 矛盾点
         · 每轮注入 top-k（关键词命中 + 轮次新鲜度），k≤6
```

**关键设计（评审最看重的点）**：LLM 是"提案者"，不是"裁判"。它给出 `{reply, deltas, memory_writes, intent}`，规则层决定接受多少；结局只由状态机算。页面提供「规则层日志」开关，评委能直接看到每次提案 vs 采纳结果——把"可校验"变成看得见的东西。

### 输出契约（每轮一次调用）

```json
{
  "reply": "……",                                  // ≤120 字，符合角色口吻
  "deltas": {"trust": -8, "fear": 5, "debt": 0},  // 整数，-10..+10
  "memory_writes": [{"who":"sailor","type":"promise","text":"答应给他面包","turn":3}],
  "intent": "deflect|reveal|threaten|bargain|silent"
}
```

失败处理：JSON 解析失败 → 重试 1 次（temperature 降到 0.3）→ 仍失败则用该角色预置兜底台词，`deltas` 全 0，前端不阻塞。

## 4. 模型选型（本机实测资源，不是拍脑袋）

本机现状：NVIDIA GB10（DGX Spark，128GB 统一内存，CUDA 13.0），已有 vLLM 0.31 venv（`/data/projs/vllm031-test/venv`）、llama.cpp、ComfyUI（8188）可出图。

| 用途 | 选型 | 理由 | 代价 |
|---|---|---|---|
| **开发/本地对局（主）** | Qwen3.8-27B NVFP4（本机已有 `260917qwen38_uncensored_nvfp4`，20G） | 角色扮演稳、指代和长上下文好；NVFP4 在 GB10 上单卡可跑 | 首字 ~1.2s、约 25-35 tok/s；占约 20G 内存 |
| 本地备选（快） | Qwen3-8B-Instruct（AWQ/NVFP4） | 延迟减半，适合调 prompt 的高频迭代 | 角色一致性与"撒谎/试探"演技略弱 |
| 线上（评委可玩） | ModelScope API-Inference：Qwen3-8B（用 1,000 魔粒） | 创空间前端 + 规则层跑 CPU，不占 GPU 配额；评委打开就能玩 | 依赖网络与魔粒额度，需降级兜底 |
| 线上备选（自包含） | Qwen3-4B-Instruct-AWQ + vLLM 跑在创空间 A10 24G | 不依赖外部 API，评分更稳 | 需抢 GPU 配额、冷启动慢 |
| 图像 | ComfyUI（qwen_image_2.1 / krea2_turbo） | 出 3 张场景背景 + 3 张剪影立绘 | 统一"剪影+雾"风格，避免 AI 味 |

**结论**：开发用 27B NVFP4；上线先用「API-Inference + 规则层 CPU」跑通，再把 4B-AWQ 自托管作为兜底方案（两条都做，切换只改一个环境变量 `LLM_PROVIDER`）。这样评委侧不依赖我本机。
