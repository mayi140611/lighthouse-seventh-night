## 1. 创意与玩法

风暴夜的孤岛灯塔，最后一班船还有三小时，救生艇只有一个位置。三个 NPC（水手、女孩、老人）各有三组可量化状态：信任、恐惧、债务，0–100，玩家侧面板实时可见。

核心玩法不是「聊得开心」，而是**用资源和信息改变三个人的状态，让他们在最后一刻自己做出选择**。玩家可以给面包/干柴/绷带、交换情报、威胁或沉默；每个 NPC 的反应由状态阈值决定，走向四个结局之一（同舟、独活、全灭、真相）。

作品亮点是「AI 只提案，规则层裁判」：模型负责把台词演好，数值变化、阈值闸门、结局判定全部由一段可单测的 Python 决定，并且**规则层日志默认对玩家展开**——玩家能看见 NPC 为什么改变主意。

## 2. 创作过程

主要开发步骤：

1. 先写状态机与结局判定表（3 NPC × 3 状态 × 4 结局），再写台词；
2. 用 Qwen 模型做对话层，规定 JSON 契约（reply / deltas / memory_writes / intent），模型越界提案直接丢弃；
3. 写规则层钳制与边界测试（94 个用例，约一半是阈值边界）；
4. 网页版（状态面板、规则日志、结局、二周目）+ 创空间部署；
5. 美术（ComfyUI 生成 3 背景 + 3 剪影立绘）、演示视频、线上的 10 轮连打自查。

AI 与个人分工：**AI 承担了约 90% 的代码与文案实现**（含状态机、测试、网页、部署脚本、美术素材生成），个人负责设定方向、审稿、拍板架构（「模型只提案」这条关键约束）、并在每次交付后做取舍与验收。没有人工逐行写代码，但每个关键判断都有人拍板。

## 3. 工具应用与体验

* **Qoder：** 本次开发**未实际使用 Qoder**（团队 Credits 已领取，但开发链路跑在本地 CLI/代理上，如实说明，不虚构使用记录）。后续如果做多文件重构，会优先试用它的仓库级改动能力。
* **魔搭 API Inference：** 调用 `Qwen/Qwen3.8-Flash-Next`（关闭 thinking）承担三个 NPC 的台词生成。实测单轮 1.9–3.1 秒，JSON 合法率 100%，0 次兜底触发（10 轮线上连打）。选它是因为中文角色语气稳定、延迟可控；thinking 打开会明显拖慢且偶尔输出解释性文字，所以关掉并在契约里强制纯 JSON。
* **赞奇科技 / 华硕 DGX Spark 节点：** 已提交云节点申请（AI NPC 方向），截至提交时仍在审核队列，**本次未使用云端节点**，作品不计这项加分。
* **本机 NVIDIA DGX Spark（GB10，128GB 统一内存）：** 全部开发与推理都在本机完成。用途：跑 Qwen 对话联调、ComfyUI 出图、Playwright 自动化自查。体验：统一内存跑 8B 级模型很轻松，出图与推理可并行；瓶颈在首包加载而非算力。
* **ComfyUI：** 生成 3 张背景与 3 张剪影立绘，共约 265KB。刻意选剪影而非写实脸，避免「AI 味」并控制体积。
* **Python 标准库 + unittest：** 规则层与契约校验不引入框架，94 个用例全绿，`python3 cli.py --demo` 可离线复现四个结局。
* **Playwright：** 线上 10 轮连打、移动端布局、断网兜底自查（iPhone 13 模拟无横向裁剪）。

## 4. 问题与解决

**问题：线上创空间一直停在「加载中」。**

现象：部署成功、状态 Running，页面转圈；日志里只有警告没有报错，很容易误判成网络问题。

排查：对比本地与平台依赖，发现平台是 Gradio 6.29.1，本地装的是 5.x；平台升级了前后端协议，旧参数被静默忽略。

解决：锁 `gradio==6.29.1`，把 `css/js` 移进 `launch()`，`Chatbot` 去掉旧参数；同时把这条写进部署文档。

改进效果：重新部署后首屏正常、10/10 轮对话通过、单轮平均 2.4 秒（最大 3.1 秒），并在此后每次部署前都先核对平台依赖版本。

另一个真实问题：**物资计数最初统计模型返回的 `memory_writes`**，模型经常忘记写，玩家给了三次面包面板还是 0，直接堵死「同舟」结局。改为由规则层从玩家输入里判定「给没给」，模型可以编台词，但不能决定行为事实。

## 5. 经验总结

可复用的三条：

1. **先写状态机和结局判定表，再写任何台词**——顺序反了，会被模型带着走，演出连贯但状态是假的。
2. **给每个阈值写边界测试**（我们一半用例是边界）——否则调参时会悄悄改变结局可达性，而且没有任何报错。
3. **把「线上版本」当独立交付物**：本地能跑 ≠ 平台能跑，版本锁和部署文档要一开始就有。

后续想改进：记忆引用命中率量化（现在只统计「引用次数」）、2–3 张关键情绪立绘、环境音（雨/浪/灯芯）、会话持久化。
