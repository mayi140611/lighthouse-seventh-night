# 概念设计：《灯塔第七夜》

目标赛项：AI+∞ 开发者创作大赛 第三期「AI 造游戏」— 故事与 AI NPC 方向，主攻「最佳 AI NPC 奖」（华硕智能体电脑）与综合奖。
硬性门槛（官方口径）：角色状态可量化 + 行为决策可由游戏规则层校验 + 对话与行为闭环 + 开源。

## 一句话
风暴夜的孤岛灯塔，三个求救者各说一套话，一个船位。你用对话核实真相，NPC 用记忆和数值回应你——最后带谁上船，是你自己算出来的结果。

## 为什么是这个方向（选择理由）
- 赛题里唯一有「硬性技术标准」的单奖项就是 AI NPC：可量化状态 + 规则校验 + 开源。标准越硬，参赛作品越少，越好拿。
- 本地推理、持久记忆、规则层判定，正好是本机 DGX Spark（128GB 统一内存）+ 本机 ComfyUI 能覆盖的组合，不需要额外资源。
- 互动叙事是网页形态，创空间部署最轻，15 分钟可通关，评委也愿意点开玩完。

## 角色状态模型（可量化，进规则层）
每个 NPC 三条 0–100 数值：`trust`（信任）、`fear`（恐惧）、`debt`（亏欠）。
- 初始值由角色设定给定（例：船员 trust 30 / fear 20 / debt 0）
- 每轮对话后，由 LLM 输出一个**结构化 delta**（JSON），只允许 `-10..+10` 区间，规则层做 clamp 与合法性校验，越界丢弃
- 关键道具/分支用阈值 gate（规则层判定，LLM 无权直接给）：
  - `trust < 40` → 船员拒绝交出船钥匙，进入「强行搜身」分支（后果：另两个 NPC 恐惧 +20）
  - `fear > 70` → 少女进入沉默锁定，本轮起不再提供新信息，只回单字
  - `debt >= 60` → 老人才会说出灯塔的真正用途（真结局钥匙）
- 状态变化必须回显：玩家侧有面板，NPC 台词里也要有可感知的对应（少说话、换称呼、重复你之前的原话）

## 记忆（这是「会记事」的核心）
- 短期：本局对话全文（约 8–12 轮/人）保留在上下文
- 长期：结构化 `memory[]`，只存「玩家做过的事」——承诺、威胁、给过的东西、说过的谎（由 LLM 每轮抽取 + 规则层落库）
- 每轮注入 top-k 相关记忆（按关键词 + 轮次新鲜度），NPC 会在后续主动引用：「你说过面包分我一半。」
- 一局结束写存档，二周目 NPC 能记住你上次的选择（放进「记忆延续」彩蛋，成本低、传播点强）

## 15 分钟流程
1. 开场（1 min）：广播里说最后一班船三小时后到，救生艇只有一个位置
2. 三轮对话（8 min）：每人 4–6 轮，可自由切换；资源有限（面包、干柴、绷带各 1 份），给谁扣谁的状态
3. 交叉验证（3 min）：三人的证词有 2 处矛盾，问对问题才出矛盾对
4. 决策（2 min）：选择带谁、留谁，是否打开灯塔的备用灯（老人才知道代价）
5. 结局（1 min）：4 个结局——「同舟」（带少女，船员死）、「守灯」（独自留下，最难的真相）、「钥匙」（带船员，但真相被带走）、「第七夜」（老人留下，循环暗示）

## 技术方案
- 前端：单页 HTML/JS，无框架负担，状态面板 + 立绘 + 打字机对话；部署魔搭创空间
- 后端：SGLang 起 Qwen3-8B（单台 DGX Spark），OpenAI 兼容接口，`response_format=json`，输出 `{reply, deltas, memory_writes, intent}`
- 规则层：纯 Python 状态机（无 LLM），负责 clamp、阈值 gate、结局判定——**这一层必须能单测**，是评审看「可校验」的地方
- 安全：LLM 输出 schema 校验失败重试 1 次，仍失败则回退到该角色预置台词（保证不崩）
- 美术：ComfyUI + Z-Image-Turbo 出 3 张立绘 + 1 张灯塔全景，统一冷色海雾调性
- 开源：规则层 + 状态机 + prompt 全开源，附 README 与 3 个单测

## 风险与对策
- 本地 8B 输出不稳定 → schema 校验 + 预置台词兜底 + 每角色温度 0.7
- 中文长上下文记忆漂移 → 结构化记忆只存事实，不存原文；每轮重算状态而非累加原文
- 工期（12.01 前）→ 先做「一角色一分支」可跑 Demo（3 天），再加到三角色（5 天），最后美术与手记（3 天）
- 「首次公开发布」限制 → 比赛期间才公开，仓库私有到提交日
